# Sheen Music · Interactive Theory Lesson Standard

**版本：** v1.0  
**状态：** 已确认的设计基线（待代码实施及视觉回归验收）  
**适用范围：** MT 音程理论教学页面；未来 MT03–05 教学页面；未来和弦记号理论课程及其他交互式音乐理论课程。  
**不适用范围：** 现有 MT Practice 判题与报告逻辑、ET 听力课程的业务逻辑、学生权限与付费系统。  
**建议仓库路径：** `docs/interactive-theory-lesson-standard.md`

## 0. 设计定位与优先级

这是一份长期维护的**教学设计、视觉表现、交互行为与组件契约**规范，而非仅供模仿的页面截图。目标是将 MT01/02 的渐进式教学逻辑与 MT06 的清晰页面框架和结构化说明融合，形成可复用的课程系统。

优先级从高到低：

1. **音乐概念正确、教学关系清楚、可理解。**
2. **不破坏现有课程的互动、答题、音频、进度及响应式行为。**
3. **相同语义的内容呈现一致。**
4. **代码复用、可维护性和视觉细节。**

不能为了统一视觉而强迫不同音乐知识使用相同图形，也不能为了简化代码而把渐进式讲解变成整页静态讲义。对于本规范未覆盖的特殊情形，应记录例外及原因，不应悄悄添加新规格。

## 1. 课程页面组成

统一使用以下概念层级（DOM 实现可以演进）：

- **页面外壳**：页眉、课程编号、进度条、主容器、页脚、安全区域。
- **课程首页**：课程编号、标题、可选导语／课程提纲、开始学习、PDF／外部练习入口。
- **教学视图**：音乐演示区（Board）、讲解区（Explanation）、步骤导航（Navigation）。
- **教学步骤**：新概念（new-concept）、延伸讲解（continuation）、练习检验（check）。
- **课程完成页**：明确的完成状态、简短总结、下一步行动、可选复习与资源入口。

所有课程应采用同一外壳和组件契约，允许不同教学步骤装载 VexFlow、SVG、键盘、音频、公式、文本或 Quiz。

## 2. T01–T06：教学内容排版

| ID | 规范 | 来源与处理 |
|---|---|---|
| T01 | **普通讲解正文**以 MT01/02 的宽松阅读感为基线。桌面／平板建议约 `1.12rem`（在 16px 根字号下约 17.9px），`line-height: 2.08`；在狭小横屏可适度紧凑，但需保持易读。不得让不同课程无故出现 16px/17.9px 两套正文标准。 | MT01/02 为主 |
| T02 | **两级强调**：核心音乐概念使用主题强调色与较高字重；一般重要术语使用正文色粗体。禁止把所有 `<strong>` 自动变成强调色。 | 融合 |
| T03 | **段落与结构化内容并存**：逐步讲解使用短段落与宽松间距；规则归纳、并列条件、对照可使用列表或表格。连续普通段落的基线间距约 `1.25em`，其他内容采用语义化间距。 | 融合 |
| T04 | **内容小标题**遵循明确的层级：模块标题 > 段落小标题 > 正文。复杂知识允许标题分层；简单步骤不强制添加标题。禁止仅为了放大文字而滥用 heading 标签。 | MT06 的清晰结构 |
| T05 | **先解释，再归纳**：新概念先用音乐图形与叙述建立理解，再用简明列表、关系式或对照总结；复习型步骤可以直接结构化回顾。 | 融合 |
| T06 | **辅助文本分语义**：演示标签、参考说明、操作提示／注释各有统一类名、字号与对比度；不再由每课任意定义 `.tiny`、`.hint` 等同义规格。 | 融合 |

**字号建议的状态：** T01 的 `1.12rem/2.08` 是已接受的视觉基线，而不是对所有标签的强制值。最终变量、移动端断点和实际可读性由实施时的视觉回归测试确定，并在此文档记录；不可静默改成另一套风格。

**建议的语义 token**（命名可与既有站点 token 对齐）：`--theory-text-body-size`、`--theory-text-body-leading`、`--theory-text-secondary-size`、`--theory-text-label-size`、`--theory-space-paragraph`、`--theory-color-emphasis`。优先兼容站点现有 Light/Dark、字体及圆角变量。

## 3. I01–I06：教学设计与交互逻辑

| ID | 规范 |
|---|---|
| I01 | **小步教学**：一个步骤只承担一个主要认知任务。新授课程参考 MT01/02 的细颗粒度；综合复习允许用模块包裹多个步骤。不规定所有课程必须有固定页数。 |
| I02 | **演示与讲解关联**：新知识的文字与当前谱例／键盘／图形应有明确对应；新授时可动态变化，规则总结时可静态对照。 |
| I03 | **按内容选媒介**：VexFlow 用于标准记谱；SVG/HTML 用于关系图与特殊交互；键盘用于音高、音程或和弦结构；音频用于必要的听觉反馈。不得强迫所有课程统一成单一渲染引擎。 |
| I04 | **即时检验**：需要确认理解时允许插入课程内 Quiz，提供明确反馈；外部练习可以补充但不能被误当成站内已评分练习。保留现有成绩／报告逻辑边界。 |
| I05 | **交互克制**：借鉴 MT06 的按钮与控制区简洁度，保留 MT01/02 有明确教学目的的交互。避免一个步骤出现多个含义相近的操作。 |
| I06 | **进度统一外观、独立语义**：统一进度条、计数及辅助标签的视觉；新授课按步骤计数，复习课可按模块计数。进度值及 ARIA 属性必须反映实际完成单位。 |

## 4. V01–V07：教学视觉与布局

| ID | 规范 |
|---|---|
| V01 | **演示区高度**：采用 MT06 更灵活的响应式思路，但允许 `compact / standard / expanded` 等语义高度档位；不要把 MT01/02 原有五线谱／键盘直接硬改成统一的 210–320px。每档须验证不裁切、不变形。 |
| V02 | **演示区留白**：优先使用统一容器 padding、gap、对齐规则；音乐图形内部允许专用排版。 |
| V03 | **演示标签**：采用 MT06 的 `board-label`、`reference-caption` 语义分层，并兼容暗色模式。 |
| V04 | **导航**：借鉴 MT06 独立、简洁的步骤导航结构；保留 MT01/02 已验证的上一步／继续行为、触控安全区域和必要状态。 |
| V05 | **课程首页**：沿用统一课程编号、标题、行动按钮；导语、课程提纲按课程复杂度选用，不能每课机械复制四条提纲。 |
| V06 | **完成页**：结合 MT01/02 明确的完成反馈与 MT06 的知识总结／下一步建议；练习、回顾、PDF 等链接依实际课程配置显示。 |
| V07 | **横屏布局**：优先保持左右分栏（左演示、右讲解）、各区独立滚动；保留既有可用的安全区域和短屏适配，逐步消除重复覆盖 CSS。 |

## 5. F01–F08：非核心教学页面框架（以 MT06 为主）

| ID | 规范 |
|---|---|
| F01 | **页面外边距**：参考 MT06，基础四周 `10px`，与 `env(safe-area-inset-*)` 取较大值；避免横屏刘海／Home Indicator 遮挡。 |
| F02 | **页眉**：统一品牌、当前步骤／模块计数、课程编号的布局与字体层级；采用 MT06 更简洁的结构，保留语义化进度信息。 |
| F03 | **页眉间距**：默认约 `14px`，短屏横屏约 `10px`；用 token／明确断点管理。 |
| F04 | **进度条**：统一约 `8px` 高，使用主题纯色进度与统一圆角；支持减少动画，进度状态应可供辅助技术读取。 |
| F05 | **主容器**：普通纵向页面最大宽度约 `520px`，横屏教学状态可扩大到双栏宽度；禁止通过固定高度裁掉内容。 |
| F06 | **首页／完成页**：独立页面状态与统一卡片外壳；不与教学滚动状态强耦合。 |
| F07 | **页脚**：采用 MT06 的统一视觉基线（约 `12px`、行高 `1.5`、适度上下留白），保持版权内容一致。 |
| F08 | **导航位置**：采用独立导航组件，布局和安全区域由统一外壳负责；不要重复出现多个同时可见的导航。 |

这里的“采用 MT06”指其**页面层级与设计方式**，不是未经验证直接复制其全部 CSS。移动端已存在的正确布局和可访问性行为必须保留。

## 6. P01–P05：渐进式讲解与自动滚动

**核心决定：渐进式累积只用于明确标记为 `continuation`（延伸讲解）的步骤，不是所有 Next 的默认行为。**

| ID | 规范 |
|---|---|
| P01 | **新增段落**：延伸步骤保留当前知识链中已有文字，在末尾加入新段落；可使用轻微渐显，不使用大幅飞入或打字机动画。 |
| P02 | **空间充足时不滚动**：仅当新段落未能完整进入可视讲解区时才自动滚动；旧段落自然向上移，保持上下文。 |
| P03 | **最小必要滚动**：让新内容完整可见，尽量保留其上方少量旧内容；避免每次强制滚到底部。只滚动讲解容器，不滚动整页或演示区。 |
| P04 | **按知识关系分组**：`new-concept` 切换或重置知识链；`continuation` 追加；`check` 切换到答题状态。不能仅根据相邻页面推断内容必然连续。 |
| P05 | **尊重阅读与动效偏好**：学生手动回看旧内容时不要无提示地抢夺滚动位置；只有明确的下一步操作可触发定位。`prefers-reduced-motion: reduce` 下立即定位，无平滑动画。 |

**跨设备**：横屏优先确保右侧独立滚动；竖屏同样支持但只在溢出时滚动；iPad／桌面不应导致整页跳动。动画持续时间和缓动曲线须与网站整体动效体系一致，避免叠加多次动画。

**实现要求**：先将新段落加入 DOM，待布局稳定后判断其可见边界，再对讲解容器执行最小滚动；不得无条件 `scrollIntoView()` 导致整个视口跳动。异步字体／谱例更新需避免重复滚动。返回前一步时恢复该步骤应显示的文本范围和合理的滚动位置。

## 7. S01–S04：步骤模型、状态和反馈

| ID | 规范 |
|---|---|
| S01 | **步骤类型明确**：每个步骤至少标记 `new-concept`、`continuation` 或 `check`；复习模块可以包含多个步骤。 |
| S02 | **演示与讲解独立更新**：步骤可只改变演示、只改变文字或同时改变两者。尽可能避免无必要地重建音频节点、VexFlow／SVG 图形与整个页面。 |
| S03 | **颜色按语义**：主题蓝紫色用于当前概念与教学选择；正文色粗体用于普通重点；成功／错误反馈分别用成功／错误语义色，并辅以文字或图标；辅助文本使用次要文字色。遵循全站 Light/Dark token，不硬编码仅适用于白底的颜色。 |
| S04 | **返回步骤时恢复状态**：返回前一步应恢复当时已揭示的文字、音乐演示、已完成的交互及合理的滚动位置；不得泄露后续步骤才应揭示的信息。状态恢复不应意外重复播放声音或重复计分。 |

### 建议的数据契约（示意，非要求逐字照搬）

```js
{
  id: 'interval-degree-03',
  kind: 'continuation', // new-concept | continuation | check
  groupId: 'interval-degree',
  title: '如何计算度数',
  explanation: [{ id: 'p3', type: 'paragraph', content: '...' }],
  board: { renderer: 'vexflow', state: 'highlight-note-pair' },
  check: null,
  completion: { nextEnabled: true }
}
```

课程框架负责**显示规则与导航状态**；每节课负责**音乐知识、交互内容与判断逻辑**。不要把音程特有字段硬编码到通用课程框架，未来和弦记号课应能使用同一容器。

## 8. 组件和样式架构

1. 优先复用网站现有设计 token，包括统一后的圆角、颜色、按钮与 Light/Dark 主题；不要新建互相竞争的全局设计体系。
2. 建立可复用的 Theory Lesson 组件样式／脚本（实际文件路径由实施审计确定），覆盖页面外壳、正文、标题、强调、提示、Board 容器、进度、导航、渐进式讲解和完成页。
3. MT01/02 现有大量内联 CSS 应逐步迁移至共享样式；MT06 的独立 CSS 可作为结构参考。迁移需分组件进行，避免一次性删除历史响应式修复。
4. 允许每课保留局部样式和渲染器，尤其是谱例、键盘、音频、公式、Quiz 等。
5. 共享脚本不得重写现有判题、计时、录音、成绩报告、学生权限或支付逻辑。
6. CSS 选择器尽量限定在理论课程根容器，避免影响 ET、作品页、乐谱页、Dashboard。
7. 交互控件需保持语义按钮、键盘可用性、焦点可见性、至少合理的触控面积；内容变化应避免不必要的焦点抢夺。

## 9. 课程作者写作与制作准则

- 每节课先写**学习目标与概念依赖关系**，再拆分步骤；不要从页面数量倒推教学内容。
- 每个新概念明确：学生要理解什么、演示显示什么、文字解释什么、何时需要检验。
- `continuation` 必须与同一知识链中的上一内容有明确延续关系；切换概念时使用 `new-concept`。
- 避免把长篇 PDF 原文直接塞入单个步骤；可通过小标题、对照表和分段揭示减轻认知负担。
- Quiz 题干、选项、正确／错误反馈与说明应有统一语义样式；题目内容与判题逻辑归课程自己维护。
- 外部练习链接需清楚标记为外部资源，不得暗示其成绩会自动回传。
- 课程首页、完成页可根据课程类型有不同内容，但应保持共同的信息层级和组件外观。

## 10. 实施范围与顺序

**本版本是规范定稿，不代表代码已经按规范修改。** 推荐未来 Codex 实施顺序：

1. 读取本规范，对 MT01、MT02、MT06 做逐项差异审计，并列出保护性回归清单。
2. 先建立共享 token 与非核心外壳（F），再统一正文语义（T）。
3. 迁移 Board、导航和响应式行为（V），逐项验证手机竖屏／横屏、iPad 与桌面。
4. 增加明确的步骤类型和状态契约（S、I），保留现有课程的教学逻辑与答题行为。
5. 仅对标记 `continuation` 的步骤接入渐进式文字追加与最小滚动（P）。
6. 验证 MT01、02、06 全流程，再将组件用于未来 MT03–05 的**新教学页**和和弦记号理论课。
7. **不得将现有 MT03–05 Practice 页面误当成待重建的教学页面。**

任何阶段出现关键回归，应先修复再进入下一阶段，不为满足形式上的统一而跳过验收。

## 11. 验收矩阵

| 类别 | 必须验证 |
|---|---|
| 设备 | iPhone 竖屏与横屏、iPad 竖屏与横屏、桌面常见宽度；特别验证矮横屏 |
| 主题 | Light、Dark；所有强调、边框、提示与反馈均可读 |
| 页面 | 首页、教学首步、中间延伸步骤、Quiz、末步、完成页、返回首页 |
| 导航 | 上一步、下一步、快速连续点击、禁用状态、进度数值与 ARIA 同步 |
| 渐进滚动 | 有空间不滚、溢出才滚、只滚讲解区、手动回看、减少动态效果、返回恢复 |
| 音乐演示 | VexFlow、键盘、SVG、音频控件不裁切、不重复播放、不丢失交互状态 |
| 教学正确性 | 文本揭示顺序、概念关系、Quiz 正确性、完成条件与原课程一致 |
| 安全边界 | Practice、报告、ET、学生权限、外部链接、网站导航不受影响 |
| 工程 | 自动测试通过；关键视口进行前后截图对比；有无法验证项须明确列出 |

## 12. 维护机制与变更规则

- 本文档为后续理论课程的**规范源（source of truth）**，新增课程应先遵循本文档，再增加课程专用实现。
- 任何有意偏离规范的页面应在对应源码附近或本文件附录记录：组件、原因、影响设备、批准时间及替代方案。
- 设计规范变化需同步更新版本号与变更记录；不能只改 CSS 不改文档。
- 建议采用：补丁版本（v1.0.x）修正措辞／实现细节；次版本（v1.x）增加兼容组件；主版本（v2）改变教学交互模型或核心布局。
- 每次 Codex 改造应明确引用本文件，并在最终报告说明哪些规范项已落实、哪些保留例外、测试与部署状态。
