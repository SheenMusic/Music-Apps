# Sheen Music · Interactive Theory Lesson Standard

**版本：** v1.1.2
**状态：** 已确认的设计基线；MT01/02/06 代码已接入，验证与设备限制见 tests/theory-learning/README.md
**适用范围：** MT 音程理论教学页面；未来 MT03–05 教学页面；未来和弦记号理论课程及其他交互式音乐理论课程。  
**不适用范围：** 现有 MT Practice 判题与报告逻辑、ET 听力课程的业务逻辑、学生权限与付费系统。  
**建议仓库路径：** `docs/interactive-theory-lesson-standard.md`

## 0. 设计定位与优先级

这是一份长期维护的**教学设计、视觉表现、交互行为与组件契约**规范，而非仅供模仿的页面截图。目标是将 MT01/02 的渐进式教学逻辑与 MT06 的清晰页面框架和结构化说明融合，形成可复用的课程系统。

优先级从高到低：

1. **音乐概念正确、教学关系清楚、可理解。**
2. **不破坏现有课程的互动、答题、音频、进度及响应式行为。**
3. **相同语义的内容呈现一致。**
4. **代码复用、可维护性和视觉细节。**

不能为了统一视觉而强迫不同音乐知识使用相同图形，也不能为了简化代码而把渐进式讲解变成整页静态讲义。对于本规范未覆盖的特殊情形，应记录例外及原因，不应悄悄添加新规格。

## 1. 课程页面组成

统一使用以下概念层级（DOM 实现可以演进）：

- **页面外壳**：页眉、课程编号、进度条、主容器、页脚、安全区域。
- **课程首页**：课程编号、标题、可选导语／课程提纲、开始学习、PDF／外部练习入口。
- **教学视图**：音乐演示区（Board）、讲解区（Explanation）、步骤导航（Navigation）。
- **教学步骤**：新概念（new-concept）、延伸讲解（continuation）、练习检验（check）。
- **课程完成页**：明确的完成状态、简短总结、下一步行动、可选复习与资源入口。

所有课程应采用同一外壳和组件契约，允许不同教学步骤装载 VexFlow、SVG、键盘、音频、公式、文本或 Quiz。

## 2. T01–T06：教学内容排版

| ID | 规范 | 来源与处理 |
|---|---|---|
| T01 | **全课共享正文体系**：以 MT06 改造前的信息层级为主要参考，MT01/02/06 及未来 Learning 一律使用同一套语义 token。普通正文从 `16px / 1.85` 校准，不再要求保留 `1.12rem / 2.08`；小屏问题应通过整体层级、空间和可滚动区域解决，不能给 MT06 另建正文体系。 | MT06 原版层级为主；全课共用 |
| T02 | **两级强调**：核心音乐概念使用主题强调色与较高字重；一般重要术语使用正文色粗体。禁止把所有 `<strong>` 自动变成强调色。 | 融合 |
| T03 | **段落与列表分层**：正文段落间距基线18px，列表采用15px/1.85、条目间距7px；列表不再无条件继承正文大小。并列规则与归纳仍使用原列表/表格，不改教学文字或揭示顺序。双栏布局的少量段落作为整体垂直居中；上下布局始终顶部排列。段落内部均保持左对齐。 | MT06 原版层级为主；全课共用 |
| T04 | **标题层级**：模块标题24px/1.4（短横屏统一21px），内容小标题17px/1.5，普通正文16px/1.85，Quiz题干18px/1.65。所有课程共享角色 token，不在 MT06 单独覆写正文；不为放大文字滥用 heading。 | MT06 原版层级为主；全课共用 |
| T05 | **先解释，再归纳**：新概念先用音乐图形与叙述建立理解，再用简明列表、关系式或对照总结；复习型步骤可以直接结构化回顾。 | 融合 |
| T06 | **辅助语义**：注释13px/1.75、演示标签13px/1.6、参考说明14px/1.7、操作/方向键提示13px/1.75。使用 `.theory-note`、`.board-label`、`.reference-caption`、`.theory-instruction` 等统一角色；音乐图形内专用音名/关系式可保留明确例外。 | MT06 原版层级为主；全课共用 |

**字号校准依据：** v1.1.0 根据实际人工预览反馈修订正文与层级；旧 1.12rem/2.08 不再作为必须保留的设计值。当前参数在共享 CSS 中集中维护，按角色而非按课程划分，未来 MT03–05 Learning 与和弦记号理论课必须直接复用。

**演示区垂直对齐规范（独立规则）：** 音乐演示内容始终在自己的演示容器内垂直居中，不受设备方向、讲解文字高度或教学步骤变化影响。居中对象是实际可见的谱线、谱号、音符、变音记号、音程标签及相关演示元素的整体，不能用100%高的空白包装层或大量透明SVG留白代替音乐边界。右上角音频按钮不参与居中。复杂演示超过可用高度时允许内部滚动，但首尾内容必须可达。

**讲解区响应式垂直对齐规范（独立规则）：** 以实际布局模式为依据，不按设备名称推测。左右双栏时，短讲解块在自己的区域内垂直居中，顶部为 `(H - h) / 2`，追加段落围绕中心平滑展开；溢出后顶部排列并内部滚动。上下布局时，讲解始终从自身区域顶部开始，按文章顺序向下追加，不因文字增加而整体上下漂移；溢出只滚动讲解区。`H` 不包含演示、页眉、进度、导航或页脚；34rem宽度、正文左对齐与16px/1.85体系不变。修改任一区的对齐不得改变另一区位置、滚动或交互。MT01/02/06、未来 MT03–05 Learning 和和弦记号理论课必须复用这两项规则。

**建议的语义 token**（命名可与既有站点 token 对齐）：`--theory-text-body-size`、`--theory-text-body-leading`、`--theory-text-secondary-size`、`--theory-text-label-size`、`--theory-space-paragraph`、`--theory-color-emphasis`。优先兼容站点现有 Light/Dark、字体及圆角变量。

## 3. I01–I06：教学设计与交互逻辑

| ID | 规范 |
|---|---|
| I01 | **小步教学**：一个步骤只承担一个主要认知任务。新授课程参考 MT01/02 的细颗粒度；综合复习允许用模块包裹多个步骤。不规定所有课程必须有固定页数。 |
| I02 | **演示与讲解关联**：新知识的文字与当前谱例／键盘／图形应有明确对应；新授时可动态变化，规则总结时可静态对照。 |
| I03 | **按内容选媒介**：VexFlow 用于标准记谱；SVG/HTML 用于关系图与特殊交互；键盘用于音高、音程或和弦结构；音频用于必要的听觉反馈。不得强迫所有课程统一成单一渲染引擎。 |
| I04 | **即时检验**：需要确认理解时允许插入课程内 Quiz，提供明确反馈；外部练习可以补充但不能被误当成站内已评分练习。保留现有成绩／报告逻辑边界。 |
| I05 | **交互克制**：借鉴 MT06 的按钮与控制区简洁度，保留 MT01/02 有明确教学目的的交互。避免一个步骤出现多个含义相近的操作。 |
| I06 | **进度统一外观、独立语义**：统一进度条、计数及辅助标签的视觉；新授课按步骤计数，复习课可按模块计数。进度值及 ARIA 属性必须反映实际完成单位。 |

## 4. V01–V07：教学视觉与布局

| ID | 规范 |
|---|---|
| V01 | **演示区高度**：采用 MT06 更灵活的响应式思路，但允许 `compact / standard / expanded` 等语义高度档位；不要把 MT01/02 原有五线谱／键盘直接硬改成统一的 210–320px。每档须验证不裁切、不变形。 |
| V02 | **留白与居中**：演示容器共用 padding/gap token（当前12px/14px），音乐图形保留专用布局。讲解容器在自己的可用显示区域内水平居中，宽度受共享 reading-width（当前34rem）限制，内部文字左对齐。使用对称 padding 和稳定的双侧滚动条占位；一段、多段、滚动条出现或 DOM 更新均不得改变水平阅读中心。讲解短内容仅在左右双栏布局沿 Y 轴垂直居中；上下布局从文字区顶部阅读。演示在两种模式下均以可见音乐整体居中；溢出内容保持可访问，不用正文对齐规则拉伸或遮盖谱面。 |
| V03 | **演示标签**：采用 MT06 的 `board-label`、`reference-caption` 语义分层，并兼容暗色模式。 |
| V04 | **导航**：借鉴 MT06 独立、简洁的步骤导航结构；保留 MT01/02 已验证的上一步／继续行为、触控安全区域和必要状态。 |
| V05 | **课程首页**：沿用统一课程编号、标题、行动按钮；导语、课程提纲按课程复杂度选用，不能每课机械复制四条提纲。 |
| V06 | **完成页**：结合 MT01/02 明确的完成反馈与 MT06 的知识总结／下一步建议；练习、回顾、PDF 等链接依实际课程配置显示。 |
| V07 | **横屏布局**：优先保持左右分栏（左演示、右讲解）、各区独立滚动；保留既有可用的安全区域和短屏适配，逐步消除重复覆盖 CSS。 |

## 5. F01–F08：非核心教学页面框架（以 MT06 为主）

| ID | 规范 |
|---|---|
| F01 | **页面外边距**：参考 MT06，基础四周 `10px`，与 `env(safe-area-inset-*)` 取较大值；避免横屏刘海／Home Indicator 遮挡。 |
| F02 | **页眉**：统一品牌、当前步骤／模块计数、课程编号的布局与字体层级；采用 MT06 更简洁的结构，保留语义化进度信息。 |
| F03 | **页眉间距**：默认约 `14px`，短屏横屏约 `10px`；用 token／明确断点管理。 |
| F04 | **进度条**：统一约 `8px` 高，使用主题纯色进度与统一圆角；支持减少动画，进度状态应可供辅助技术读取。 |
| F05 | **主容器**：普通纵向页面最大宽度约 `520px`，横屏教学状态可扩大到双栏宽度；禁止通过固定高度裁掉内容。 |
| F06 | **首页／完成页**：独立页面状态与统一卡片外壳；不与教学滚动状态强耦合。 |
| F07 | **页脚**：采用 MT06 的统一视觉基线（约 `12px`、行高 `1.5`、适度上下留白），保持版权内容一致。 |
| F08 | **导航位置**：采用独立导航组件，布局和安全区域由统一外壳负责；不要重复出现多个同时可见的导航。 |

这里的“采用 MT06”指其**页面层级与设计方式**，不是未经验证直接复制其全部 CSS。移动端已存在的正确布局和可访问性行为必须保留。

## 6. P01–P05：渐进式讲解与自动滚动

**核心决定：渐进式累积只用于明确标记为 `continuation`（延伸讲解）的步骤，不是所有 Next 的默认行为。**

| ID | 规范 |
|---|---|
| P01 | **按布局渐进展开**：同组 continuation 保留既有节点、追加新段落。双栏模式测量内容包装层位置并采用约200–300ms（当前240ms）FLIP/Web Animations 让旧段落平滑上移；上下模式不执行维持居中的整体位移，只让新段轻微渐显；双栏不能仅淡入新段而让旧文字瞬间跳位；上下布局不应为居中移动旧文字。不重建无须更新的演示。 |
| P02 | **按布局模式对齐**：固定的讲解滚动视口与内部内容层分离。左右双栏的短内容整体垂直居中，追加后重新居中但不滚动视口；上下布局始终顶部排列，追加只向下延伸。水平方向保持34rem最大阅读宽度、容器居中和正文左对齐。禁止在可滚动容器上直接强制 justify-content:center 导致顶部不可达，也不用固定 top/margin 偏移模拟居中。 |
| P03 | **溢出与阅读焦点连续**：溢出后顶部排列、视口独立滚动；双栏临界步骤通过内容层过渡与最小平滑滚动衔接，不能突然跳到顶部；上下布局保持原有顶部起点，仅做必要滚动。目标偏移在未施加动画的布局中测量并限制于自然滚动范围，不因动画的临时溢出增加滚动。新段尽量完整可见，过长单段从段首阅读，所有历史文字可回看。只滚讲解区，不滚页面，不调用 scrollIntoView；演示、页眉、导航及水平阅读中心稳定。 |
| P04 | **类型与恢复不变**：new-concept 重置知识链、同组 continuation 追加、check 保留原答题规则。快照保存实际内容节点与视口滚动位置；后退、多步返回、再次前进及溢出返回短内容或横竖屏切换均按实际布局恢复正确文字数量、居中/顶部模式、滚动、演示和 Quiz 状态，不泄露未来文字、不重复段落/音频/计分。 |
| P05 | **读者控制与减少动态**：仅明确继续触发自动定位；滚轮、触摸、指针或聚焦阅读区后的键盘阅读既取消排队定位也停止执行中的程序滚动。讲解溢出且聚焦阅读区时上/下方向键优先服务滚动；Home/End/PageUp/PageDown/空格保持原生阅读。左/右方向键仍可切换步骤；未溢出的内容与其他区域保留既有四方向导航，控件原生行为优先。减少动态模式保持相同居中/滚动布局，立即定位、无渐显和位移。必须通过真实浏览器连续帧/录屏验证旧文字移动，而不只验最终 DOM。 |

**跨设备**：横屏优先确保右侧独立滚动；竖屏同样支持但只在溢出时滚动；iPad／桌面不应导致整页跳动。动画持续时间和缓动曲线须与网站整体动效体系一致，避免叠加多次动画。

**实现要求**：先将新段落加入 DOM，待布局稳定后判断其可见边界，再对讲解容器执行最小滚动；不得无条件 `scrollIntoView()` 导致整个视口跳动。异步字体／谱例更新需避免重复滚动。返回前一步时恢复该步骤应显示的文本范围和合理的滚动位置。居中由 CSS 自适应可用高度，不逐帧用 JavaScript 改写 top/margin；仅 compositor 处理过渡。

## 7. S01–S04：步骤模型、状态和反馈

| ID | 规范 |
|---|---|
| S01 | **步骤类型明确**：每个步骤至少标记 `new-concept`、`continuation` 或 `check`；复习模块可以包含多个步骤。 |
| S02 | **演示与讲解独立更新**：步骤可只改变演示、只改变文字或同时改变两者。尽可能避免无必要地重建音频节点、VexFlow／SVG 图形与整个页面。 |
| S03 | **颜色按语义**：主题蓝紫色用于当前概念与教学选择；正文色粗体用于普通重点；成功／错误反馈分别用成功／错误语义色，并辅以文字或图标；辅助文本使用次要文字色。遵循全站 Light/Dark token，不硬编码仅适用于白底的颜色。 |
| S04 | **返回步骤时恢复状态**：返回前一步应恢复当时已揭示的文字、音乐演示、已完成的交互及合理的滚动位置，并按当下实际布局及内容高度恢复双栏居中或顶部滚动模式；不得泄露后续步骤才应揭示的信息。状态恢复不应意外重复播放声音或重复计分。 |

### 建议的数据契约（示意，非要求逐字照搬）

```js
{
  id: 'interval-degree-03',
  kind: 'continuation', // new-concept | continuation | check
  groupId: 'interval-degree',
  title: '如何计算度数',
  explanation: [{ id: 'p3', type: 'paragraph', content: '...' }],
  board: { renderer: 'vexflow', state: 'highlight-note-pair' },
  check: null,
  completion: { nextEnabled: true }
}
```

课程框架负责**显示规则与导航状态**；每节课负责**音乐知识、交互内容与判断逻辑**。不要把音程特有字段硬编码到通用课程框架，未来和弦记号课应能使用同一容器。

## 8. 组件和样式架构

1. 优先复用网站现有设计 token，包括统一后的圆角、颜色、按钮与 Light/Dark 主题；不要新建互相竞争的全局设计体系。
2. 建立可复用的 Theory Lesson 组件样式／脚本（实际文件路径由实施审计确定），覆盖页面外壳、正文、标题、强调、提示、Board 容器、进度、导航、渐进式讲解和完成页。
3. MT01/02 现有大量内联 CSS 应逐步迁移至共享样式；MT06 的独立 CSS 可作为结构参考。迁移需分组件进行，避免一次性删除历史响应式修复。
4. 允许每课保留局部样式和渲染器，尤其是谱例、键盘、音频、公式、Quiz 等。
5. 共享脚本不得重写现有判题、计时、录音、成绩报告、学生权限或支付逻辑。
6. CSS 选择器尽量限定在理论课程根容器，避免影响 ET、作品页、乐谱页、Dashboard。
7. 交互控件需保持语义按钮、键盘可用性、焦点可见性、至少合理的触控面积；内容变化应避免不必要的焦点抢夺。

## 9. 课程作者写作与制作准则

- 每节课先写**学习目标与概念依赖关系**，再拆分步骤；不要从页面数量倒推教学内容。
- 每个新概念明确：学生要理解什么、演示显示什么、文字解释什么、何时需要检验。
- `continuation` 必须与同一知识链中的上一内容有明确延续关系；切换概念时使用 `new-concept`。
- 避免把长篇 PDF 原文直接塞入单个步骤；可通过小标题、对照表和分段揭示减轻认知负担。
- Quiz 题干、选项、正确／错误反馈与说明应有统一语义样式；题目内容与判题逻辑归课程自己维护。
- 外部练习链接需清楚标记为外部资源，不得暗示其成绩会自动回传。
- 课程首页、完成页可根据课程类型有不同内容，但应保持共同的信息层级和组件外观。

## 10. 实施范围与顺序

以下为实施与后续新课接入顺序；MT01/02/06 的本地实施状态见附录：

1. 读取本规范，对 MT01、MT02、MT06 做逐项差异审计，并列出保护性回归清单。
2. 先建立共享 token 与非核心外壳（F），再统一正文语义（T）。
3. 迁移 Board、导航和响应式行为（V），逐项验证手机竖屏／横屏、iPad 与桌面。
4. 增加明确的步骤类型和状态契约（S、I），保留现有课程的教学逻辑与答题行为。
5. 仅对标记 `continuation` 的步骤接入渐进式文字追加与最小滚动（P）。
6. 验证 MT01、02、06 全流程，再将组件用于未来 MT03–05 的**新教学页**和和弦记号理论课。
7. **不得将现有 MT03–05 Practice 页面误当成待重建的教学页面。**

任何阶段出现关键回归，应先修复再进入下一阶段，不为满足形式上的统一而跳过验收。

## 12. 维护机制与变更规则

## 附录：当前显示实现契约（v1.1.2）

- 外壳/语义排版为 `MT-Intervals/shared/styles/learning-base.css`；可选谱例/键盘/Quiz 为 `learning-components.css`；显示控制为 `shared/learning/theory-lesson.js`。仅根节点 `data-theory-lesson` 选择这些规则，site 主题/圆角仍是唯一上游。
- 步骤显式提供 `id / kind / groupId / boardKey / size`，以及独立的 `board()`、`explanation()`、可选 `mount()`（绑定原 Quiz）。`boardKey` 相同则不重建演示；返回已访问步骤复用节点、监听与滚动位置。框架不推断答案、不产生音符、不保存学生数据。
- `continuation` 的解释函数提供原课程的累计 HTML；框架只在同一 group 且既有节点确为前缀时追加新节点。新概念替换内容，检验步骤按原课呈现；不根据编号推断累积。若前缀不一致则按作者提供的完整内容替换，不拼出未经确认的讲义。
- 全课共用 MT06 原版层级：模块24px（短横屏21px）、小标题17px、正文16px/1.85、列表15px/1.85；段落间距18px。所有值均使用共享语义 token；`.theory-note` 为注释，`.board-label` 为演示标签，`.reference-caption` 为参考说明，`.key-accent`（兼容作者现有内容）/`.theory-concept` 为核心概念。普通 strong 保持正文粗体，不全变主题色。
- 竖屏 Board 的 compact/standard/expanded 分别适用于简短谱例/键盘、一般演示、复习/复杂控制；具体尺寸在共享 CSS 唯一定义。小屏 expanded 允许内部滚动，保证正文和底部导航仍有空间；横屏 ≥600px 左右分栏，两区各自可滚，谱面按比例缩放、键盘水平滚动，不拉伸琴键。
- `TheoryLesson.create({board, explanation, viewport})` 将内容与滚动视口显式分离。MT01/02 的 #stepBody、MT06 的 #lessonContent 保持固定滚动视口；内部 .theory-explanation（#stepExplanation / #reviewExplanation）承接原文字及 Quiz DOM。讲解视口为纵向 flex，内容层 flex:none；默认上下布局 margin-block:0，定义双栏grid的同一布局规则才设置 margin-block:auto。双栏正剩余空间均分，溢出自动外边距归零；上下布局始终顶部可达。没有逐帧高度/偏移修补。布局随内容和实际双栏/上下模式变化自动重算。
- 演示区使用独立 .theory-board-content 内在高度内容层和安全自动外边距；现有满高谱例包装改为跟随实际谱例。共享显示运行时按可见SVG图元（过滤隐藏/透明内容）拟合纵向viewBox，并保留描边安全内边距；所有音符路径、谱表坐标和横向渲染宽度不变。HTML音名标签与音乐SVG作为同组，音频按钮独立固定。旋律引线通过 getScreenCTM 映射坐标，并响应共享 theory-board-layout 事件在缓存恢复及容器变宽/变高时重新定位；音名标签沿用原相对音符定位函数。MT02性质图保留有意隐藏的grid单元，使用按已显示文字边界计算的局部视口去除透明占位，既有揭示类和单元结构不变。复杂演示超高时整体从滚动起点可访问。
- 延伸前记录讲解内容层视觉位置，提交追加后的无变换布局并确定最小滚动范围；仅实际双栏grid执行240ms FLIP，上下布局不作整体位移，新段在两种模式均渐显。定位延后两帧，revision 取消过期操作；自然 scrollHeight 在 FLIP 前测量并限制目标，避免变换临时溢出造成过滚。使用 overflow-anchor:none 避免锚定竞争。动画类清理不得给原本无 class 的段落遗留空属性而破坏节点前缀比较。
- 快照仅存内部内容节点及外层滚动值，返回或切换布局时由 CSS 重新得到双栏居中/上下顶部模式。读者操作取消排队/执行中的自动定位；外层 tabindex=0 支持键盘阅读，焦点在其本身且内容溢出时，上/下方向键用于滚动；左/右始终保留步骤导航。窗口尺寸变化取消旧布局中排队的自动定位。减少动态模式不创建 FLIP/渐显动画，布局和定位仍正确。
- MT01/02 返回或再次前进到已访问步骤不自动重播音频；演示按钮仍可主动播放；同音频组前进保留录音连续性。每次仅一个播放按钮，避免复用演示时堆叠控件。
- MT06 四模块各自 new-concept，保留模块内归纳、转位/复音程度数按钮和外部练习，不强制拆分为延伸段落。
- MT01/02 原有完整教学文字和 Quiz 函数保留。已有回顾型累计段落（如旋律/和声分类）保持原顺序；没有把它们重新组织为新知识结构。
- 全站五档圆角与折叠标准不变；普通按钮/Quiz 使用 control、容器使用 card；真圆音频按钮和琴键非对称轮廓保留教学例外。


### 通用谱表与键盘交互

- 单行、独立展示的谱表不显示高音谱号左侧无意义的起始小节线；VexFlow 使用 `setBegBarType(VF.Barline.type.NONE)`，不使用白块覆盖或 CSS 隐藏整个图组。连续结构中的内部小节线、结束线、五条谱线、谱号、音符及变音记号必须保留。自绘 SVG 已无该线时不额外处理。
- MT01/02/06 共用方向键控制：左/上为上一步，右/下为继续；必须经过现有按钮的 disabled/aria-disabled 与课程门槛，不绕过 Quiz。
- 输入、可编辑区域、Quiz、演示内控件及其他原生交互优先处理自身键盘事件；共享快捷键只在教学视图且无修饰键时工作，不拦截 Enter/Space。导航按钮自身可用方向键操作相邻教学步骤。
- 精确指针桌面显示简洁提示；触屏默认不显示，在真正使用框架方向键后显示。提示预留固定空间，显隐不得挤压正文或移动导航；按钮提供 aria-keyshortcuts。
